# 复习队列（Review Queue）

> `todolist.md` 是**入口队列**——哪些视频还没处理。
> 这里是**出口队列**——哪些内容还没复习。两者是同一个架构的两面：
> git 同步的 markdown 队列 + 多机 agent 认领，只是方向相反。
>
> 为什么需要它：整条 pipeline 原本终止于「validator exit 0 + 双推完成」，
> 但遗忘曲线在那一刻才刚开始。没有这张表，一篇 10000 字文章在 7 天后
> 能留下的大约就是 30 秒速览那 5 条——而那 5 条读者在第 1 分钟就拿到了。
>
> 完整规则见 `SKILL.md` 的「Review Gate」一节。

## 使用说明

- **状态**取值：`待复习` / `复习中（谁在复习）` / 走完 D+35 后移入「已归档」。
- **认领**：把状态改成 `复习中（机器名）`，避免多台机器同时开考同一条。
- **怎么考**：优先用 `<stem>-deck.tsv`（Anki 导入后由 Anki 自己排程），
  没装 Anki 就让 agent 直接从 tsv 里抽题口头考。上次错题优先。
- **D+7 的推荐形态**：先听 3 分钟版讲稿（M14）再答 5 张卡。
  听是重新激活，答才是检索；比"重读一遍 10000 字"的依从性高一个数量级。
- 本文件跟随仓库默认双推（GitHub + Gitee）。任何一次复习或状态变更后都应提交推送，
  否则其他机器上的 agent 看到的是过期队列。
