# 记忆卡组规格（Deck Spec）v3.0

> 卡组是**按需产物**（v5.1 起）：默认不生成，只有用户明确要求为某个视频做卡组时才产出。
> 本规格只在那时加载。
> 文件名：`<日期>-<source>-<video_id>-<slug>-deck.tsv`，与主文同 stem 加 `-deck` 后缀，同目录。
> 生成：`python3 scripts/build_deck.py <主文.md>` 出草稿，**agent 必须逐条过一遍**再交付。

---

## 第 0 章 · 为什么卡组是记忆的主力

主文是「读」的产物。蓝图自己在附录里写明：

> ⚠️ Takeaway 不是检索练习。它是作者写好的判断句，读者只是"再读一遍并点头"
> （recognition），不产生长期记忆。

这个判断是对的，但 v2.1 的资源分配没跟上——实测生成型内容只占全文 9–14%，其余全是"读"。

更关键的是时间维度。整条 pipeline 终止于 `validate exit 0 + 双推完成`，但遗忘曲线在那一刻才刚开始。蓝图曾称 M09 系统性回顾 = 间隔重复，这是概念错误：**间隔重复的「间隔」单位是天和周，不是段落之间的 300 字**；同一次阅读里重复三遍叫 massed practice（集中练习），不是 spaced practice。

**卡组解决的正是这一件事**：它不新增任何内容——数字、自测题、证伪信号本来就在主文里——只是把它们重排成**跨天可考**的形态。

**v3.0 变更（随 blueprint v5.0）**：讲错风险清单与 🚧 边界随主文一起砍除，「纠错 / 边界」两类卡下线。加上 v2.0 已下线的「辨析 / 速查 / 概念 / 关系」，卡组现在只剩三个来源——**综合**（S5 闭卷自测）、**证伪**（S6 我错了的信号）、**数字 / 数字反向**（S4 数字锚点表）。

来源变少不等于卡变少：数字锚点表通常能出 20 组以上双向卡，真正的约束一直是 32 张的上限和人工取舍，不是候选不够。

## 第 1 章 · 格式

TSV，三列，无表头（`#` 开头为注释行，Anki 会忽略）：

```
正面 <TAB> 背面 <TAB> 标签
```

导入 Anki：文件 → 导入 → 字段分隔符 Tab → 允许 HTML **关闭** → 第三列映射为 Tags。

**标签格式**：`<video_id>::<类别>::<可信度字>`

```
类别      来源                        考的是什么
──────────────────────────────────────────────────────
综合      S5 闭卷自测                  跨章机制      ← 价值最高
证伪      S6 我错了的信号              判断的边界
数字      S4 数字锚点表                事实
数字反向  同上，反向出题               事实（防单向记忆）
──────────────────────────────────────────────────────
```

`可信度字` 取 `实` / `推` / `测`，由数字锚点表的「来源强度」经 `scripts/credibility.py` 的唯一映射得出，**不由感觉决定**。validator 会逐个数字比对卡组标签与主文来源强度。

## 第 2 章 · 三条硬约束

```
① 原子化
   一卡一事实。段落切片不是卡——读者会整段"眼熟"过去，什么都没提取。

② 双向
   数字类必须正反两问：
     正向  「英伟达 AI 加速器份额——数值是多少？」→ 80%-90%
     反向  「「80%-90%」在本篇指的是什么？」      → 英伟达 AI 加速器份额
   只出正向，读者会形成只认前半句的假记忆：听到数字认不出它属于谁。
   两张卡必须同进同出，截断时不得只留一张。

③ 可信度进标签
   ::实/::推/::测 写进 Anki tag，让可信度分层在**每次复习时**都被重新过一遍，
   而不是只在初读时看过一眼。卡背对非【实】项一律带「对外引用加『视频称』」。
```

## 第 3 章 · 数量与取舍

```
下限   20 张（validator 拦）
默认   32 张（build_deck.py --cap，0 = 不限）
上限   建议不超过 40 —— 超了说明没做取舍，复习依从性会崩
```

优先级（截断时从后往前砍）：

```
综合 > 证伪 > 数字/数字反向
```

**截断必须明示**。`build_deck.py` 会在文件头与终端同时报告丢弃了多少张候选——静默截断会让人误以为"已经全覆盖"。

**卡数不够怎么办**：先回头看主文，`综合` 少说明 S5 出题不足，`证伪` 少说明 S6 立场不足 2 个，`数字` 少说明各章数字锚点表挖得不够。**卡组补不了主文的缺口，只能暴露它。**

**数字卡怎么挑**：脚本按文档顺序截断，结果往往是前几章的次要数字占满额度、后几章的核心数字被砍掉。人工复核时**按"讲出去会被追问"的重要度重挑**，不要照单全收——这是最值得花时间的一步。

## 第 4 章 · 人工复核清单

机械生成能到 80%，最后 20% 是判断力。交付前逐条检查：

```
□ 查表就能答的删掉        「HBM 堆了几层」是记忆，不是理解
□ 语义重复的合并          综合卡与证伪卡偶尔撞车
□ 陈述句改成问句          正面不是问句 = 这张卡在做识别
□ 背面控制在 3 行内        长背面等于没考
□ 数字卡正反成对          截断后检查一遍
□ 非【实】项带对外措辞     「视频称」不能漏
□ 证伪卡问的是"看到什么"   不是"你怎么看"——必须是可观测事件
```

## 第 5 章 · 复习节奏

卡组配 `workspace/review-queue.md`，节奏 **D+1 / D+3 / D+7 / D+16 / D+35**。
到期扫描：`python3 scripts/review_due.py`。

D+1 那次尤其重要——它兑现的是 S1 读前预判埋下的预期违背：**猜错过的地方，第二天重考一遍，记忆强度显著高于任何重读。**

---

## 第 6 章 · 禁止清单

```
❌ 卡数 < 20
❌ 缺 ::实/::推/::测 标签
❌ 正面重复
❌ 数字卡只有正向没有反向
❌ 把 Takeaway 原样搬成卡（它是判断句，不是问题）
❌ 静默截断（不报告丢弃数量）
❌ 未经人工复核就交付 build_deck.py 的原始输出
❌ 产出已下线的 辨析/概念/速查/关系/纠错/边界 六类卡（它们的来源已不存在）
```
